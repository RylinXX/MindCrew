# 设计契约 · 数字员工交付物（PPT / Word / 合同）

> 补齐「多智能体数字员工（生成 ppt、合同等）」能力。基于已有 POI 依赖（`poi-ooxml` + `poi-scratchpad`），不新增 Maven 依赖。

## 1. 目标

1. Crew 调研报告（`agent_task.final_report` Markdown）一键导出 `.pptx` / `.docx`
2. 通用「文档生成」接口：Markdown → PPTX / DOCX
3. 合同生成：内置「采购合同 / 服务合同」两个模板，按字段填充 DOCX

## 2. 后端类清单

| 文件 | 职责 |
|---|---|
| `service/office/MarkdownParser.java` | 轻量 Markdown 解析：`# / ## / ###` 标题、`- ` / `* ` 列表、`1. ` 有序列表、普通段落、代码块（忽略样式按段落输出）、表格（按行转文本） |
| `service/office/OfficeDocumentService.java` | `byte[] toPptx(title, subtitle, markdown)`、`byte[] toDocx(title, markdown)`、`byte[] contractPptx?` 不需要、`byte[] toContractDocx(template, fields)` |
| `service/office/ContractTemplateRegistry.java` | 模板元数据（id/name/type/fields 定义）+ 字段校验 + 合同正文渲染（纯文本占位符 `{{partyA}}` 等，程序画 DOCX 排版，**不依赖二进制模板文件**） |
| `service/office/OfficeDeliverableService.java` | 从 `agent_task` 取报告，鉴权（`userId` 或 admin），生成字节 + 文件名 |
| `controller/OfficeController.java` | `/api/v2/office/**` |
| 修改 `controller/CrewController.java` | 追加 `GET /api/v2/crew/tasks/{taskId}/deliverable?format=pptx|docx` |

包都放 `com.simon.MindCrew.*`；不要新增 Mapper 之外的扫描配置。

## 3. 生成规则

### 3.1 PPTX（16:9，`slideSize 13.333in x 7.5in`）

- 封面：标题（40pt 加粗，主题色 #3D5AFE）+ 副标题（16pt 灰）+ 底部「Generated by MindCrew」
- 目录页：一级标题列表
- 每个 `##` 一级章节 → 1~N 页（每页最多 6 条 bullet，超出自动分页）
- `###` 作为 bullet 的加粗小标题；`-` 列表 → bullet；普通段落 → bullet（截断 200 字）
- 页脚：页码 + 「MindCrew · Agentic RAG」
- 无 `##` 时按段落分页
- 纯文本清洗：去掉 Markdown 标记、`**`、`` ` ``、链接语法只留文字

### 3.2 DOCX

- 标题（Heading）、章节（`#` → Heading1、`##` → Heading2、`###` → Heading3；文档标题已作为参数单独排版）、列表样式、正文段落 11pt、行距 1.5
- 页脚：`MindCrew 数字员工 · {yyyy-MM-dd}`
- 中文乱码防护：导出时 `Content-Type: application/vnd.openxmlformats-officedocument.*`，文件名用 RFC 5987 `filename*=UTF-8''...`

### 3.3 合同模板

`GET /api/v2/office/templates` →
```json
[
  {"id":"purchase","name":"采购合同","description":"...","fields":[{"key":"partyA","label":"甲方","required":true}, ...]},
  {"id":"service","name":"服务合同", "...": "..."}
]
```

`POST /api/v2/office/contract` body：
```json
{"template":"purchase","fields":{"partyA":"某某公司","partyB":"MindCrew 科技","amount":"100000","signDate":"2026-11-10","deliveryDate":"2026-12-01","productName":"知识库系统","contactA":"张三","contactB":"李四"}}
```
必填字段缺失 → `BusinessException(PARAM_ERROR)`；金额自动大写（阿拉伯数字转中文大写，如 `壹拾万元整`）。
返回 DOCX 字节流，文件名 `采购合同-{partyB}-{yyyyMMdd}.docx`。

## 4. 接口契约

| 方法 | 路径 | 入参 | 出参 |
|---|---|---|---|
| GET | `/api/v2/office/templates` | - | 模板列表 |
| POST | `/api/v2/office/pptx` | `{title,subtitle?,markdown}` | `application/vnd...presentation` 字节流 |
| POST | `/api/v2/office/docx` | `{title,markdown}` | `application/vnd...wordprocessingml` 字节流 |
| POST | `/api/v2/office/contract` | 见 3.3 | DOCX 字节流 |
| GET | `/api/v2/crew/tasks/{taskId}/deliverable?format=pptx` | format=pptx/docx/md | 文件流（`md` 直接返回 `finalReport` 原文） |

- OfficeController：返回 `ResponseEntity<byte[]>`，在响应头显式设置 `Content-Type`（不使用 `produces`，避免全局异常 JSON 与文件流协商产生 406）；鉴权：登录即可（`/api/v2/office/**` 保持 authenticated）。
- Crew 交付物：校验 `task.userId == 当前用户` 或 admin → 403 否则；`finalReport` 为空 → 400「报告尚未生成」。
- 生成失败统一 `BusinessException(500, "文档生成失败: ...")`，并在日志记录。

## 5. 前端契约

- `src/api/office.ts`：`listTemplates`、`generatePptx`、`generateDocx`、`generateContract`、`downloadCrewDeliverable`（都用 `responseType:'blob'`）。
- `src/utils/download.ts`：`downloadBlob(blob, filename)`（从 `content-disposition` 解析文件名，取不到用默认名）。
- CrewView：报告完成后，在报告操作区加「导出 PPT / 导出 Word」按钮（loading 状态 + 成功提示）。
- 新增 `/deliverables` 页面（菜单「工作台 → 数字员工」）：三种模式 Tab「PPT 生成 / Word 生成 / 合同生成」，左侧表单 + 右侧预览（PPT 用页数统计 + 大纲预览；合同用字段表单），生成后自动下载。
