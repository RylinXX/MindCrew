# 本地启动说明（无 Docker 环境）

> 本机没有 Docker / Homebrew，也未安装 MySQL、Redis、Milvus、MinIO。
> 因此按「轻量本地模式」启动：MySQL + Redis 本地运行，Milvus / MinIO 关闭，LLM 使用本地 Mock。
> 需要完整能力时，请在安装 Docker 后改用 `docker-compose.yml` 起四件套。

## 三、降级说明（重要）

| 能力 | 当前状态 | 原因 | 如何恢复 |
|---|---|---|---|
| 向量语义检索 | 关闭（`milvus.enabled=false`） | 本机无 Milvus | 安装 Docker 后 `docker compose up -d milvus`，重启后端并去掉该参数 |
| 关键词/BM25 检索 | 可用 | MySQL 全文索引 + 应用层 BM25 | — |
| 文档上传 / 对象存储 | 不可用 | 本机无 MinIO，OSS Key 未验证 | 启动 MinIO 或改 `storage.type=oss` 并填有效 Key |
| 大模型回答 | **Mock 示例答案** | 原 `BAILIAN_API_KEY` 返回 401 | 在「AI 配置 → 大模型 Provider」填入真实 Key 并测试启用，或改 `llm_provider` 表后重启 |
| 语音 / 钉钉 / SSO | 接口可用，未联调 | 无外部服务/应用 | 按文档配置后联调 |

> Mock 模型返回固定示例文本，用于验证页面、流式输出、会话落库、客服轮询等链路，**不代表真实问答质量**。

## 四、启动 / 停止 / 状态

```bash
bash scripts/dev-local.sh status   # 查看 5 个组件端口
bash scripts/dev-local.sh stop     # 停止后端/前端/Redis/MySQL/Mock
bash scripts/dev-local.sh start    # 全部启动（MySQL 数据保留在 /tmp）
```

注意：`/tmp` 在重启后可能被清理。若 `/tmp/mindcrew-runtime` 不存在，需要重新下载 MySQL/Redis 并解压到该目录，脚本会自动初始化数据目录与导入 SQL。
需要持久化时，建议把 `mysql-data` 与 Redis 数据迁移到用户目录，或直接用 Docker 全量部署。

## 五、切换到真实大模型

1. 登录后进入「AI 配置 → 大模型 Provider」，编辑「阿里云百炼 · DashScope」；
2. 填入有效 API Key，模型填 `qwen-plus`（或 `qwen-turbo` / `qwen-max`），点击「测试」；
3. 测试通过后「启用」，`AiConfigHolder` 会热切换模型，无需重启；
4. 或直接改库：

```sql
UPDATE llm_provider
SET base_url = 'https://dashscope.aliyuncs.com/compatible-mode',
    chat_model = 'qwen-plus'
WHERE is_active = 1;
```

密钥字段 `api_key_enc` 为 AES-GCM 加密值，建议通过页面保存，不要手写明文。
