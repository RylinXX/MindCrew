# 数字员工交付物使用手册（报告导出 / PPT / Word / 合同）

> 适用接口：`/api/v2/office/**`、`/api/v2/crew/tasks/{taskId}/deliverable`
> 适用角色：登录用户；Crew 报告只能导出自己的任务（admin 例外）
> 实现基础：复用项目已有的 POI 依赖（`poi-ooxml` + `poi-scratchpad`），不新增 Maven 依赖。

## 一、能力概览

| 能力 | 入口 | 产物 |
|---|---|---|
| Crew 调研报告导出 | `GET /api/v2/crew/tasks/{taskId}/deliverable`（`format=pptx / docx / md`） | PPTX / DOCX / Markdown 原文 |
| Markdown 转 PPT | `POST /api/v2/office/pptx` | `.pptx` 字节流 |
| Markdown 转 Word | `POST /api/v2/office/docx` | `.docx` 字节流 |
| 合同生成 | `POST /api/v2/office/contract` | `.docx` 字节流 |
| 合同模板列表 | `GET /api/v2/office/templates` | 模板元数据（字段定义） |

前端入口：菜单「工作台 → 数字员工」页面 `/deliverables`（PPT / Word / 合同三种模式），以及 Crew 任务完成后报告操作区的「导出 PPT / 导出 Word」按钮。

## 二、Crew 报告导出

### 2.1 使用方式

1. 在 Agent 调研页面完成一次任务，等待状态为 `COMPLETED`；
2. 点击「导出 PPT」或「导出 Word」；也可以直接下载 Markdown 原文（`format=md`）；
3. 服务端从 `agent_task.final_report`（Markdown）生成文件并直接下载。

### 2.2 规则

| 项 | 说明 |
|---|---|
| 参数 | `format`：`pptx`（默认）/ `docx` / `md` |
| 鉴权 | `task.userId` 必须等于当前登录用户，或当前用户为 admin；否则 403 |
| 报告为空 | `final_report` 为空时返回 400「报告尚未生成」 |
| 文件名 | `MindCrew-{清洗后标题}-{taskId}-{yyyyMMdd}.{ext}`；标题取任务问题（最多 40 字），中文按 RFC 5987 编码 |
| 失败 | 统一返回「文档生成失败」并记录日志 |
| 空入参 | `title` 或 `markdown` 为空时返回 400 |
| 文件名 | 普通文档为 `{清洗后标题}-{yyyyMMddHHmmss}.pptx / .docx`；Crew 导出沿用任务标题 |

## 三、PPT 生成规则

生成 16:9 演示文稿，页面尺寸 `13.333in × 7.5in`：

| 页面 | 规则 |
|---|---|
| 封面 | 标题 40pt 加粗（主题色 `#3D5AFE`）+ 副标题 16pt 灰 + 底部「Generated by MindCrew」 |
| 目录页 | 章节标题列表（最多 10 条，超出显示省略号）；少于 2 个章节时不出目录 |
| 章节页 | 每个一级/二级标题（`#` / `##`）一个章节，每页最多 6 条 bullet，超出自动分页 |
| 条目 | `###` 作为 bullet 的加粗小标题；`-` / `*` 列表项转 bullet；普通段落、表格、代码块也转 bullet，单条截断 200 字 |
| 页脚 | 页码 + 「MindCrew · Agentic RAG」（封面不加） |
| 无标题时 | 按段落内容分页 |
| 文本清洗 | 去掉 Markdown 标记、`**`、反引号；链接只保留文字 |

请求示例：

```json
{
  "title": "企业知识库选型调研",
  "subtitle": "MindCrew 数字员工",
  "markdown": "## 调研背景\n- 现状：文档分散\n## 结论\n- 统一知识入口"
}
```

## 四、Word 生成规则

| 项 | 规则 |
|---|---|
| 标题 | 文档标题居中、22pt 加粗主题色；正文标题按 Markdown 层级映射 Heading 1/2/3 |
| 章节 | `#` → Heading 1，`##` → Heading 2，`###` → Heading 3 |
| 列表 | `-` / `*` 转 `•` 开头段落；`1.` 按序号输出 |
| 正文 | 11pt，行距 1.5 |
| 页脚 | `MindCrew 数字员工 · yyyy-MM-dd` |
| 输出 | 响应头显式 `Content-Type: application/vnd.openxmlformats-officedocument.wordprocessingml.document`（不走 `produces` 协商，避免异常 JSON 406），文件名 RFC 5987 编码 |

## 五、合同生成

### 5.1 使用方式

1. 先调 `GET /api/v2/office/templates` 拿模板与字段定义；
2. 前端按字段渲染表单；
3. 提交 `POST /api/v2/office/contract`，字段校验通过后直接下载 DOCX。

### 5.2 模板列表返回结构

```json
[
  {
    "id": "purchase",
    "name": "采购合同",
    "description": "适用于企业向供应商采购货物或软件的购销合同",
    "fields": [
      { "key": "partyA", "label": "甲方（采购方）", "required": true }
    ]
  },
  {
    "id": "service",
    "name": "服务合同",
    "description": "适用于技术咨询、系统运维、知识库运营等服务类合作",
    "fields": [
      { "key": "partyA", "label": "甲方（委托方）", "required": true }
    ]
  }
]
```

### 5.3 采购合同字段表（`template=purchase`）

| key | 字段名 | 必填 | 说明 |
|---|---|---|---|
| `partyA` | 甲方（采购方） | 是 | 采购方名称 |
| `partyB` | 乙方（供应方） | 是 | 供应方名称 |
| `productName` | 采购内容 | 是 | 货物/软件名称及规格 |
| `amount` | 合同金额（元） | 是 | 数字，可带 `¥`、逗号、`元`；自动转中文大写 |
| `deliveryDate` | 交付日期 | 否 | 缺省「双方另行约定」 |
| `signDate` | 签订日期 | 否 | 缺省当天（`yyyy-MM-dd`） |
| `contactA` | 甲方联系人 | 否 | 缺省「—」 |
| `contactB` | 乙方联系人 | 否 | 缺省「—」 |

### 5.4 服务合同字段表（`template=service`）

| key | 字段名 | 必填 | 说明 |
|---|---|---|---|
| `partyA` | 甲方（委托方） | 是 | 委托方名称 |
| `partyB` | 乙方（服务方） | 是 | 服务方名称 |
| `serviceName` | 服务内容 | 是 | 本次服务名称/范围 |
| `amount` | 合同金额（元） | 是 | 数字，自动转中文大写 |
| `servicePeriod` | 服务期限 | 否 | 缺省「双方另行约定」 |
| `signDate` | 签订日期 | 否 | 缺省当天（`yyyy-MM-dd`） |
| `contactA` | 甲方联系人 | 否 | 缺省「—」 |
| `contactB` | 乙方联系人 | 否 | 缺省「—」 |

### 5.5 生成规则

- 必填字段缺失或为空 → 400，提示「XX不能为空」；
- 金额必须是非负数字，去掉 `¥`、`￥`、`,`、`，`、`元`、空格后解析；负数或非数字 → 400；超过 `10^16-1` → 400「超出可处理范围」；
- 金额统一保留 2 位小数，同时生成中文大写（支持「万 / 亿 / 万亿」分组，如 `100000` → `壹拾万元整`，`1000.50` → `壹仟元伍角`）；
- 正文中未提供的占位符统一渲染为「—」，不会把 `{{xxx}}` 漏到文档里；
- 文件名为 `{模板名}-{乙方名称}-{yyyyMMdd}.docx`，乙方名称会过滤非法字符并截断到 32 字；
- 合同编号格式 `MC-yyyyMMdd-4位随机数`。

请求示例：

```json
{
  "template": "purchase",
  "fields": {
    "partyA": "某某公司",
    "partyB": "MindCrew 科技",
    "amount": "100000",
    "signDate": "2026-11-10",
    "deliveryDate": "2026-12-01",
    "productName": "知识库系统",
    "contactA": "张三",
    "contactB": "李四"
  }
}
```

## 六、前端下载约定

- 所有下载接口返回二进制流，前端使用 `responseType: 'blob'`；
- 统一调用 `src/utils/download.ts` 的 `downloadBlob(blob, filename)`：从 `content-disposition` 解析文件名，取不到时用默认名；
- 文件名中文通过 RFC 5987 `filename*=UTF-8''...` 传递，避免乱码；
- 生成按钮需有 loading 态，成功后给出提示。

## 七、常见问题

| 现象 | 排查方向 |
|---|---|
| 下载的文件打不开 | 检查响应是否被网关二次编码；确认 `Content-Type` 未被改写 |
| 中文文件名乱码 | 浏览器需支持 RFC 5987；确认前端从 `content-disposition` 解析而不是硬编码文件名 |
| 导出 403 | Crew 任务不属于当前用户，且当前用户不是 admin |
| 导出 400「报告尚未生成」 | 任务还没到 `COMPLETED`，`final_report` 为空 |
| 金额大写不对 | 检查传入金额是否为数字、是否带单位；系统会先清洗再转换 |
| PPT 页数太多/太少 | 按 `##` 章节与每页 6 条 bullet 自动分页；减少空章节或过长的段落 |
| 合同字段缺失报错 | 按 `/templates` 返回的 `required` 标记补齐必填项 |
